# ساختار مالکیت داده شعبه‌ها و اشتراک‌گذاری مدیریت‌شده زمین‌نگار

## چرا نباید تمام اکسل‌های قبلی را پاک کرد؟

در نسخه قبلی `survey_cases.created_by` و `import_batches.user_id` هویت ثبت‌کننده را نگه می‌داشتند و دسترسی کارمند از همان ستون تعیین می‌شد. وقتی کارمند حذف نرم می‌شود، سوابق باقی می‌مانند اما برای کارکن تازه قابل دیدن نیستند. **حذف اطلاعات اکسل مشکل مجوز را حل نمی‌کند** و تکراری بودن شماره پرونده‌های موجود همچنان پابرجاست.

در اصلاحیه حاضر:
- `survey_cases.branch_id` و `import_batches.branch_id` مرز مالکیت دائمی شعبه هستند.
- `created_by` و `user_id` ثبت‌کننده تاریخی باقی می‌مانند؛ هیچ انتقال مجوزی آن‌ها را عوض نمی‌کند.
- ارتباط‌های ثبت‌کننده در Eloquent با `withTrashed` نام حساب‌های حذف نرم‌شده را نشان می‌دهند.
- `case_access_grants` مجوز مشاهده یا مشاهده+ویرایش پرونده دستی یا **کل گروه اکسل** را برای کارمند هم‌شعبه ثبت می‌کند.
- فقط منیجر مجوز را ثبت یا لغو می‌کند. ویرایش پرونده مشترک فقط با `can_edit` مجاز است؛ **حذف پرونده یا گروه اکسل مشترک هرگز مجاز نیست**.
- با انتقال کارمند به شعبه جدید، مجوزهای شعبه قبلی حذف می‌شوند. تاریخچه همچنان متعلق به شعبه قبلی است.

## پیش‌نیاز مهم

از آخرین نسخه پروژه به‌همراه **تمام اصلاحیه‌های قبلی** استفاده کنید. این ZIP تنها فایل‌های تغییر‌یافته را دارد؛ فایل‌های دیگر را پاک نکنید.

ابتدا از دیتابیس در phpMyAdmin با Export خروجی SQL بگیرید و مسیر `storage/app/imports` را هم پشتیبان بگیرید.

## نصب

بسته را در ریشه پروژه Laravel ادغام کنید و در محیط توسعه اجرا کنید:

```bash
php artisan migrate
php artisan optimize:clear
npm run dev
php artisan test --filter=BranchOwnedDataAccessTest
```

مسیر جدید منیجر: `/manager/data-access`.

در این صفحه فهرست گروه‌های اکسل و پرونده‌های دستی را می‌توان بر اساس شعبه جست‌وجو و از میان کارکن همان شعبه، دریافت‌کننده مجوز را انتخاب کرد. برای افراد حذف نرم‌شده، نام ثبت‌کننده قبلی قابل نمایش است.

## داده‌های قدیمی بدون شعبه

فایل `SAFE_SQL_EXISTING_DATA.sql` شامل **گزارش پیش از تغییر و نمونه SQL انتقال پرونده‌های فاقد شعبه** است. در آن `999` را فقط بعد از بررسی و با شناسه واقعی شعبه جایگزین کنید؛ اگر پرونده‌های قدیمی متعلق به چند شعبه‌اند، انتقال باید جداگانه و با انتخاب شناسه‌های مناسب انجام شود.

بعد از نسبت دادن داده‌ها به شعبه، در پنل `/manager/data-access` به کارمند فعلی دسترسی دهید. لازم نیست شماره پرونده، ثبت‌کننده اصلی یا رکورد مالی تغییر کند.

## درخواست حذف بارگذاری‌های قبلی

فایل `OPTIONAL_HIDE_OLD_IMPORT_HISTORY.sql` فقط یک دستور **اختیاری و غیرفعال (کامنت شده)** برای نرم‌حذف تاریخچه گروه‌های اکسل دارد. اگر آن را اجرا کنید، گروه‌های قبلی از فهرست‌های عادی پنهان می‌شوند، اما پرونده‌های مرتبط باقی می‌مانند و ثبت دوباره آن‌ها شماره پرونده تکراری خواهد داشت. بنابراین **اگر می‌خواهید گروه‌های قبلی را به کارمند جدید واگذار کنید، این دستور را اجرا نکنید**.

هیچ دستور `TRUNCATE`, `DROP` یا `DELETE FROM survey_cases` در بسته وجود ندارد. حذف فیزیکی import_batches با وجود کلیدهای خارجی پرونده و مجوز خطرناک است.

## وضعیت تست و محدودیت‌ها

فایل‌های PHP با `php -l` و TSX با پردازش نحوی TypeScript بررسی می‌شوند؛ این برابر با اجرای تست‌های واقعی روی Laravel، مرورگر و دیتابیس پروژه شما نیست. اول روی دیتابیس آزمایشی اجرا کنید.

اگر حساب کارمند **واقعاً به‌صورت فیزیکی از users حذف شده** یا شناسهٔ ثبت‌کننده از پرونده پاک شده باشد، نام ثبت‌کننده صرفاً از طریق بکاپ‌ها یا سوابق معتبر قابل بازیابی است؛ `withTrashed` فقط حذف نرم را پوشش می‌دهد.
